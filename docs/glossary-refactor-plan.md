# 术语表功能重构计划

## 目标

将术语表从“LLM 翻译优化”中独立出来，作为设置页顶级功能，并让 LLM 翻译与支持上下文的 ASR 服务共享同一套术语来源。

本次重构保持现有 JSON v1 导入导出、在线订阅、缓存、条件请求、离线使用、来源排序、优先级去重、刷新状态和安全校验不变，不改变其他产品功能。

## 设计边界

- 顶级配置使用 `glossary`，包含 LLM 开关、ASR 开关和有序术语来源。
- 本地术语和在线订阅使用同一份来源列表，列表顺序即优先级。
- LLM 使用完整术语条目，包括目标词、分类和大小写设置。
- ASR 仅使用来源词，按大小写不敏感方式去重，不对识别结果做文本替换。
- ASR 注入集中在有效运行时配置构建阶段，不在各 Provider 中重复实现。
- 用户手工 ASR Context 优先，其次是共享术语，最后是 VRCX 房间上下文。
- 上下文长度使用当前 ASR 服务声明的限制；超限时舍弃后续自动内容，不修改持久化的手工 Context。
- 当前只接入已有 Context 通道的云端 ASR 服务，不升级本地 Whisper 依赖。

## 实施阶段

### 1. 配置与迁移

- 将配置版本升级到 v25。
- 新增顶级 `GlossaryConfig`：
  - `llm_enabled`
  - `asr_enabled`
  - `sources`
- 两个开关默认启用，以保持旧 LLM 行为并启用共享 ASR 术语。
- 将 v24 及更早版本的 `translation.prompt.glossary_sources` 无损迁移到顶级配置。
- 保留来源 ID、顺序、启用状态、本地条目和订阅信息。

验收：旧配置可加载；新配置可保存并再次加载；JSON 字段契约稳定。

### 2. 共享术语运行时

- 使用独立 `GlossaryStore` 管理配置、订阅状态和缓存。
- 提供面向消费者的窄接口：
  - LLM 有效条目
  - ASR 有效来源词
- 保留跨来源优先级、去重和 500 条总限制。
- 保留 JSON v1、ETag、Last-Modified、离线缓存、HTTPS/环回 HTTP 校验和兼容 API。

验收：本地来源与订阅来源按顺序合并；禁用来源不生效；订阅状态与缓存行为不回退。

### 3. LLM 接入

- 翻译请求和 Prompt 预览统一读取共享术语表。
- `llm_enabled` 关闭时不向 Prompt 注入术语。
- 从翻译优化界面和配置中移除术语表管理入口。

验收：开关即时生效；翻译 Prompt 的其他设置保持不变。

### 4. ASR 接入

- 在统一的有效 ASR 配置构建入口追加术语，不修改各 Provider 请求实现。
- 复用现有 Provider Context 通道和服务级字符上限。
- 保持手工 Context、共享术语、VRCX 上下文的固定优先级。
- 不支持 Context 的服务和本地 Whisper 不注入术语。
- 术语配置或订阅内容变化时，仅重建受影响的云端捕获会话，不重新加载本地模型。

验收：Qwen、Fun-ASR、Groq 等现有 Context 通道可收到共享术语；关闭 ASR 开关时不注入；超限行为稳定。

### 5. 设置界面

- 新增顶级“术语表”设置分类。
- 提供 LLM 与 ASR 两个独立开关。
- 迁移现有术语编辑器、导入导出和订阅管理界面。
- 复用现有设置区块、开关、按钮、对话框和响应式样式。

验收：桌面与窄屏布局均与现有设置风格一致；原有术语管理能力可用。

### 6. 验证

- 后端配置、迁移、订阅、LLM 开关、ASR 去重、上下文优先级、字符限制和重载判定测试。
- 前端构建、设置派生逻辑、校验、术语工具和 i18n 测试。
- Rust 格式检查、完整测试、前端构建、前端测试、i18n 检查和 `git diff --check`。
